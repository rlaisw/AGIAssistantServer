# Implementation Plan: Infographic URLs reachable by remote clients

**Feature**: specs/052-infographic-remote-access

## Technical Context

- Chat UI: Next.js 16 (`ai-chat-landing/`), served at `https://agia.tvb.com.hk` via nginx → :3000.
- Infographics are generated by the sidecar's `antv_infographic` tool (spec 046) and served by the sidecar on port `28080` at `/infographics/<id>/…`; today the tool result embeds `http://localhost:28080/infographics/<id>/…` into the answer text.
- Link rendering: `components/markdown.tsx` special-cases the `/infographics/` URL family (📌 blue link, spec 046).
- Identity: Entra sessions (spec 050) + profile registry (spec 051) give `session → oidHash → slug`.
- Sidecar container `agentic-rag` publishes 28080 to the host only; not reachable from client browsers.

## Key Decisions

- **D1 — Relative URLs from the tool**: the `antv_infographic` tool result URL becomes a relative path instead of a loopback absolute URL: `/infographics/p/<slug>/<id>/` when the profile slug is present in the tool call, else `/infographics/<id>/`. No host literal is emitted (FR-002).
- **D2 — Same-origin proxy route**: a Next.js route `app/infographics/[[...path]]/route.ts` proxies `/infographics/…` to the sidecar `http://127.0.0.1:28080/infographics/…`, streaming bytes and preserving content types.
- **D3 — Ownership enforcement**: for `/infographics/p/<slug>/…` the route resolves the session identity's slug and refuses (403) on mismatch; plain `/infographics/<id>/…` requests pass through (legacy/anonymous posture, FR-008).
- **D4 — Legacy rewriting in the renderer**: `markdown.tsx` rewrites any `http://localhost:28080/infographics/…` occurrence in stored answers to same-origin `infographics/…` links (FR-006), so historical conversations stay usable without data migration.
- **D5 — No storage or generation change**: infographic files, IDs, and page content are untouched (FR-004).

## Constraints

- Single-user local-trust posture: no new public exposure; the proxy serves only what the sidecar serves today.
- No schema/data migration: old answers keep working via renderer rewriting.
- Profile-slug URLs are enforced by the proxy; plain URLs remain local-trust.

## Risks

- Streaming large assets through Next route — mitigated by direct passthrough with no buffering.
- Slug absence in the Dify tool payload (legacy lane) — falls back to the plain form (FR-008).

## Error Handling (added)

- Proxy failures are always honest envelopes: 403 (ownership mismatch / unauthenticated profiled request), 400 (malformed slug), 404/400 (unknown or malformed id), 502-style envelope when the infographic service is unreachable (test-plan H1–H5).
- The proxy must fail closed: on upstream errors it never fabricates content and never caches errors.
- No directory listing, no path traversal (path is strictly `^/infographics/(p/<slug>/)?<id>/<asset>`).
